## 2. PRD (현재 버전)

### 2.1 서비스 개요

직무 분야와 지원 기업, 채용 공고(JD) 또는 자기소개서 요약을 바탕으로 면접 준비에 참고할 질문을 탐색하고, 질문을 저장하거나 반복 연습할 수 있도록 돕는 웹서비스 프로토타입이다.

 `data/interview_sample_questions_300.json`에 저장된 사전 준비 질문 데이터를 불러와 선택한 직무에 해당하는 질문을 보여주는 방식으로 동작한다.

### 2.2 대상 사용자

- 취업 및 면접을 준비하는 사용자
- 지원 직무와 관련된 예상 질문을 탐색하고 싶은 사용자
- 질문을 저장하고 반복해서 답변 연습을 하고 싶은 사용자

### 2.3 해결하려는 사용자 문제 및 핵심 가치

사용자는 지원 직무와 관련된 면접 질문을 찾고 유형별로 정리하는 데 어려움을 겪을 수 있다. 질문의 의도나 평가 목적을 파악하기 어렵고, 연습할 질문을 저장해 다시 확인하는 과정도 번거로울 수 있다.

**핵심 가치:** 지원 직무에 맞는 면접 질문을 탐색하고 질문 의도를 파악하며, 필요한 질문을 저장해 반복적으로 답변을 준비하도록 돕는다.

### 2.5 MVP (최소 기능 제품)

현재 프로토타입에서 확인할 MVP 범위는 다음과 같다.

1. 사용자가 직무를 선택한다.
2. 선택한 직무에 해당하는 질문 목록을 확인한다.
3. 질문 유형 필터와 키워드 검색으로 질문을 찾는다.
4. 질문 상세 화면에서 질문 내용과 질문 의도를 확인한다.
5. 질문을 저장하거나 저장 해제한다.
6. 질문별 메모를 작성하고 저장한다.
7. 마이페이지에서 저장한 질문 및 질문 세트를 확인한다.
8. 플래시카드 방식으로 질문을 반복 연습한다.

### 2.7 User Flow

**질문 탐색 흐름**

1. 사용자가 홈 화면에 진입한다.
2. 직무 분야를 선택하고, 필요하면 지원 기업명과 JD 또는 자기소개서 요약을 입력한다.
3. 질문 탐색을 실행한다.
4. 시스템이 JSON 샘플 질문 데이터에서 선택한 직무의 질문을 표시한다.
5. 사용자가 질문 유형 필터 또는 키워드 검색으로 질문을 좁힌다.
6. 질문 상세 화면에서 질문 내용과 질문 의도를 확인한다.
7. 필요한 질문을 저장하거나 메모를 작성한다.

**저장 질문 복습 흐름**

1. 사용자가 마이페이지로 이동한다.
2. 저장된 질문 또는 질문 세트를 확인한다.
3. 복습할 질문을 선택한다.
4. 플래시카드 방식으로 질문을 확인하며 답변 연습을 한다.

### 2.9 데이터 관리 (JSON / API / 사용자 데이터)

#### 공통 샘플 질문 JSON

- 파일: `data/interview_sample_questions_300.json`
- 형식: JSON 배열
- 총 데이터: 300개
- 직무: 5개, 직무별 60개

| 직무 | 질문 수 |
|---|---:|
| 프론트엔드 개발 | 60 |
| 백엔드 개발 | 60 |
| AI·데이터 | 60 |
| 서비스 기획·PM | 60 |
| 마케팅 | 60 |
| **합계** | **300** |

각 질문 객체의 필드는 다음과 같다.

| 필드 | 설명 |
|---|---|
| `id` | 질문 고유 식별자 |
| `job` | 직무 식별값 |
| `job_name` | 화면에 표시할 직무명 |
| `category` | 질문 유형 |
| `topic` | 질문 주제 |
| `question` | 질문 본문 |
| `intent` | 질문 의도 및 평가 목적 |

#### 데이터 구분 및 저장 원칙

| 데이터 종류 | 저장 위치 | 데이터 성격 |
|---|---|---|
| 기본 면접 질문 300개 | `data/interview_sample_questions_300.json` | 모든 사용자에게 공통으로 제공하는 샘플 데이터 |
| 북마크 / 저장 질문 | 브라우저 `localStorage` | 브라우저에 저장되는 개인 상태 |
| 질문별 메모 | 브라우저 `localStorage` | 브라우저에 저장되는 개인 상태 |
| 선택 직무 및 기업명 등 | 브라우저 `localStorage` | 브라우저에 저장되는 입력 및 선택 상태 |
| 질문 세트 관련 사용자 데이터 | 브라우저 `localStorage` | 브라우저에 저장되는 개인 데이터 |

- `localStorage` 키: `wireframe_interview_data`
- JSON 원본에는 개인별 북마크나 메모를 기록하지 않는다.
- 공통 질문 데이터와 사용자별 상태를 분리한다.
- 현재 저장 방식은 브라우저 단위 로컬 저장이며 로그인 기반 서버 저장이나 기기 간 동기화는 구현되어 있지 않다.

#### JSON 로딩 및 API 현황

- 질문 데이터는 `fetch()`를 사용해 `data/interview_sample_questions_300.json`에서 불러온다.
- JSON 로딩은 `file://` 직접 실행보다 로컬 웹 서버 환경에서 확인하는 것을 권장한다.

### 2.10 생성형 AI 도구 활용

#### 현재 서비스 내 AI 적용 상태

| 항목 | 현재 상태 |
|---|---|
| AI 기반 실시간 질문 생성 | 미구현 |
| 사전 준비 질문 데이터 활용 | 구현됨 |
| 질문 표시 방식 | 선택 직무를 기준으로 JSON 샘플 질문 조회 및 표시 |

현재 화면의 질문 생성 동작은 실제 AI 모델이 질문을 새로 생성하는 기능이 아니다. 사전에 준비된 JSON 질문 중 선택한 직무에 해당하는 데이터를 보여주는 프로토타입 기능이다.

#### 향후 적용 방향

- 직무, 지원 기업, JD 및 자기소개서 요약을 참고하는 맞춤형 질문 생성 기능 검토
- 질문 유형별 질문 생성 및 기존 질문 보완 기능 검토
- 질문 의도 및 답변 가이드 생성 기능 검토

#### 개발 과정에서 사용한 생성형 AI 도구 기록

현재 제공된 README와 프로젝트 자료만으로는 기획·개발 과정에서 사용한 생성형 AI 도구의 정확한 제품명, 사용 시점 및 작업 범위를 확인할 수 없다. 확인되지 않은 도구를 사용했다고 기재하지 않으며, 실제 사용 내역이 확인되면 도구명과 활용 업무를 기록한다.

### 2.11 저장 및 사용자 상태

- 브라우저 `localStorage` 키: `wireframe_interview_data`
- 저장 대상: 선택 직무, 지원 기업명, 질문별 북마크 및 메모, 질문 세트 관련 사용자 데이터
- 현재 저장 방식은 브라우저 단위 로컬 저장이다. 로그인 기반 서버 저장이나 여러 기기 간 동기화는 구현 범위에 포함되지 않는다.

### 2.12 디자인 및 기술 기준

- 모바일 우선 화면 구성
- 회색과 흰색 중심의 Lo-Fi 와이어프레임 스타일
- HTML, CSS, JavaScript 기반
- Tailwind CSS CDN 및 Font Awesome CDN 사용
- 샘플 질문은 별도 JSON 파일에서 `fetch()`로 로드

### 2.13 현재 버전의 범위 및 제한사항

- 실제 AI 모델을 통한 질문 생성은 아직 연결되지 않았다. 현재 생성 버튼은 샘플 질문 데이터를 선택 직무 기준으로 표시하는 프로토타입 동작이다.
- 데이터는 테스트용 샘플 질문이며 실제 채용 기업의 공식 면접 질문을 의미하지 않는다.
- 사용자 데이터는 현재 브라우저 `localStorage`에 저장된다.
- 서버 로그인, 사용자별 클라우드 저장, 외부 서비스 연동은 현재 버전에서 제공하지 않는다.
- 최근 생성 면접 세트의 마이페이지 이동 및 마이페이지 중심 개인화 구성은 후속 개선 항목이다.

### 2.14 후속 개선 항목

- 상단의 `AI WIREFRAME ENGINE` 및 소개 문구 정리

- 저장한 질문이 마이페이지에 일관되게 표시되는지 확인 및 개선
- 답변 가이드 기능 추가
- 검색 필터 구성 개선
- 메인 내비게이션 구조 확정
- 실제 AI 질문 생성 API 연동 검토

## 4. 실행 방법

1. ZIP 압축을 해제한다.
2. 프로젝트 폴더를 연다.
3. 로컬 웹 서버를 통해 `index.html`을 실행한다.
4. `data/interview_sample_questions_300.json` 파일이 지정된 위치에 있는지 확인한다.

JSON 데이터는 `fetch()`로 불러오기 때문에 파일 탐색기에서 `index.html`을 직접 여는 `file://` 방식보다 VS Code Live Server 등 로컬 웹 서버 사용을 권장한다.

## 5. 유지보수 원칙

- 새 이미지나 아이콘은 `asset/`에 저장한다.
- 스타일 변경은 `css/style.css`에서 관리한다.
- 화면 기능 변경은 `js/app.js`에서 관리한다.
- 공통 샘플 질문 데이터는 `data/`에서 관리한다.
- 개인별 북마크와 메모 등 사용자 상태를 공통 샘플 JSON에 직접 기록하지 않는다.
- 기능 또는 요구사항이 변경되면 이 문서의 PRD와 변경 이력을 함께 갱신한다.
- 구현 상태가 변경되면 기능 우선순위, MVP 범위, 사이트맵 및 User Flow도 함께 확인한다.
